## Mathematical specification and corrections

* Eqs. 1–3: depth is camera **z**, not Euclidean range. Back-project pixel centers after the same crop/resize transform used on the image. Use `T_ego_from_camera` and `K` with declared axes; reject singular K and nonrigid transforms.
* Top-K: retain original softmax mass (do not renormalize selected depths). Weighted cell mean normalizes by deposited mass. Auxiliary depth classification operates only on available positive finite camera-z labels, bounded by configured bins.
* Eqs. 4–5: gather/concatenate on union of active cells with explicit zero filling. A pure-PyTorch submanifold sparse convolution is supplied: neighborhoods use sorted integer keys and searchsorted, preserve coordinates, and apply trainable kernel matrices. No spconv dependency and no claim of CUDA sparse-kernel speed. AMPM/ERA intentionally densify afterward; this is a hybrid sparse/dense design.
* Eq. 6: pool over active cells; empty scenes return zero descriptors. Beta is sigmoid of a learned scalar. Eq. 8 gamma is a softmax mixture of depthwise kernels, with pointwise channel mixing. This efficient kernel factorization is an introduced design choice.
* Eqs. 11–17: directional means and squeeze/excitation with residual concatenation as written. Dense attention can populate neighbors; support masking only affects AMPM scene descriptors.
* Eqs. 19–24: numerically stable BCE with logits; within-instance margin variance, between-instance margin distance, small center regularizer. Offset/height MSE normalized by valid lane count, rather than all BEV cells (documented correction). Empty targets yield differentiable zeros. Height missingness has an independent validity mask. Collision cells containing multiple lane instances are ignored.
* Coordinates: ego x forward, y left, z up. BEV rows index x and columns index y; manuscript ΔY becomes residual from lateral cell center. Grid is half open. Camera x right, y down, z forward. Multi-view features share encoder, calibrated lifting aggregates all views.
* Eqs. 25–27: TP/FP/FN accumulated over frames; one-to-one maximum-cardinality threshold matching precedes overlap/distance quality tie-breaks. No lane true negatives. Eq. 28 is used only for binary pixel diagnostics.

## Missing information and independent choices

Defaults: feature width 64, embedding dimension 4, depth bins 2–80m with 40 centers, K=3, segmentation threshold .3; BEV x[0,80), y[-12,12), resolution .5m; z[-4,6). AMPM dilations 1/2/3, 4 depthwise base kernels. These are not manuscript specifications. Selection is dense during initial warm-up epochs, then thresholded with an explicit minimum candidate budget to avoid empty early features. Selection indices remain nondifferentiable; selected probabilities and values receive gradients. No straight-through derivative claim.

Image-only data train the image-plane instance head with AMPM/ERA. They never acquire synthetic point clouds or guessed metric coordinates. Calibrated BEV mode supports real point clouds or explicit camera-only lifting. A portable sparse voxel point MLP replaces a deep sparse VoxelNet backbone; investigate capacity before making comparisons. No database is needed for immutable image/point datasets; SQLite stores experiment status, configs and metrics only. Model/lane predictions use JSONL/NPZ/checkpoints.

## Feasibility and validation plan

CPU execution can validate operators, gradient flow, training/checkpoint/resume, inference, dataset adapters, reports and diagnostic ablations. It cannot establish the reported RTX 3090 FPS, GFLOPs or full benchmark accuracy. Acquire a small **real**, annotated subset if publicly accessible; keep it out of version control, record provenance, and label all such training as a limited engineering experiment. Analytic operator fixtures are tests, not experimental datasets. Preserve all seven manuscript tables and seven figures under explicitly attributed manuscript assets. New figures must come from actual executed logs.
